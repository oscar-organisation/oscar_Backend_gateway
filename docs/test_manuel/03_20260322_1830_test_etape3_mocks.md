# Test Manuel - Etape 3 : Generateur de Token et Simulateur Media (Avance)

**Date de validation :** 22-03-2026 19:40
**Composant vise :** Backend / Services annexes (Simulateur Robot)

## Objectif du test
Valider manuellement que le simulateur diffuse le flux video de substitution vers la salle de reunion RTC, et que le generateur de JSON accouche d'un ticket d'entrée valide.
Le simulateur repose desormais sur l'abstraction matérielle OpenCV (couplée en fond à GStreamer et FFmpeg) permettant l'injection de fichiers MP4, de flux USB natifs ou de mires.

## Prerequis
- Le conteneur serveur WebRTC LiveKit doit etre allume (Etape 2).

## Execution pas-a-pas

### 1- Regler la camera
Modifier le fichier `backend/env/.env.dev`. 
Choisissez une valeur pour l'option `MEDIA_SOURCE_TYPE` :
- `test_pattern` : Une mire generee dans le CPU.
- `video_file` : La lecture en boucle fichier cible par `MEDIA_VIDEO_PATH`.
- `usb_camera` : La capture des pilotes webcams locaux via `MEDIA_DEVICE` (soit 0 par defaut).

### 2- Allumer et verifier le Robot virtuel
Construire et demarrer les services avec la console PowerShell :
```powershell
cd c:\PROJET-HETIC\PROJET-fin-etude\OSCAR\Code\V1\backend\infrastructure\livekit
docker compose up -d --build
docker logs oscar-media-simulator
```
**Preuve de bon fonctionnement** : La fenetre de texte des logs indique un succès si ces phrases apparaissent dans l'ordre: "Connecte au serveur LiveKit", "Flux WebRTC publie" et "Demarrage de l'encodage".

### 3- Generer l'autorisation du Front
Lancer le fichier executif independant pour forger le contrat d'interface :
```powershell
cd c:\PROJET-HETIC\PROJET-fin-etude\OSCAR\Code\V1\backend\services\token-generator
docker run --rm --env-file ../../env/.env.dev oscar-token-generator
```
Le bloc texte JSON restitue toutes les pieces dont le navigateur a besoin pour se lier a la simulation actuelle.
